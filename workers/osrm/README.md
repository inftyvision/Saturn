# OSRM — real road routing for the fleet map

`packages/db` and the rest of `workers/` are empty on purpose (see the root
`CLAUDE.md`: no backend until the flows are approved). This is the one
exception, and it's infrastructure rather than product backend: a self-hosted
routing engine so the map can draw the road a driver actually takes instead
of the straight "not a route" line the corridor draws by default. `FleetMap`
falls back to that straight line whenever this isn't running — nothing
depends on it staying up.

No API key, no vendor lock-in — same reasoning the tile choice already
documents in `FleetMap.tsx`. [OSRM](https://project-osrm.org) is open source,
and [Geofabrik](https://download.geofabrik.de) publishes a free, small
(~15 MB) Guyana-only OSM extract, so the whole thing runs on a laptop.

## One-time setup (already done for this checkout)

```bash
cd workers/osrm
mkdir -p data
curl -sL -o data/guyana-latest.osm.pbf \
  https://download.geofabrik.de/south-america/guyana-latest.osm.pbf

# Windows/Git Bash: MSYS_NO_PATHCONV=1 prefix stops bash from rewriting the
# /opt/... and /data/... container paths into Windows paths.
MSYS_NO_PATHCONV=1 docker run --rm -v "$(pwd)/data:/data" osrm/osrm-backend \
  osrm-extract -p /opt/car.lua /data/guyana-latest.osm.pbf
MSYS_NO_PATHCONV=1 docker run --rm -v "$(pwd)/data:/data" osrm/osrm-backend \
  osrm-contract /data/guyana-latest.osrm
```

`data/` is gitignored — everything in it is either downloaded or generated by
the two commands above. Re-run them only if the map needs fresher OSM data;
the routing server itself never touches the source `.pbf`.

## Running it

```bash
cd workers/osrm
docker compose up -d
```

Serves HTTP routing on `localhost:5555`. The app reads this from
`OSRM_URL` (`apps/ops/.env` — defaults to `http://localhost:5555` if unset).

```bash
curl "http://localhost:5555/route/v1/driving/-58.2694,6.4531;-58.1783,6.8342?overview=full&geometries=geojson"
```

## What this is not

Not deployed anywhere, not in the request path of anything but the map's
route line, and not a dependency the app fails without — `apps/ops/src/lib/route.ts`
fails soft to no route when this isn't reachable. It's a local dev
convenience for seeing the real feature, the same spirit as the driver app's
`SimProvider` standing in for a location stack that doesn't exist yet.
